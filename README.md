# Waste Sorter

Учебный ML-проект: определение материала одного предмета по фотографии — пластик,
бумага, стекло, металл, органика, опасные отходы или прочее.
Проверяем, помогает ли фото принять верное решение быстрее текстового справочника.

Подготовлены дизайн и Python-каркас. Данные, обученная модель, API и пилот пока
не реализованы. Численные цели в документе — гипотезы, а не результаты.

## Как это будет работать

1. Пользователь загружает фото одного предмета в веб-демо поверх FastAPI.
2. Лёгкий классификатор возвращает материал или отказ от ответа.
3. Возможная опасность имеет приоритет над обычной инструкцией; низкая уверенность
   требует пересъёмки, проверки маркировки или обращения к справочнику.
4. Условия приёма определяются отдельным проверенным профилем оператора.
   Без профиля результат — `unknown`, а не обещание подходящего контейнера.
5. Добровольный фидбэк поступает в обучение только после проверки метки
   и при отдельном согласии на хранение фото.

Материал и приём — разные понятия. `other` не означает «не перерабатывается».
PET, HDPE, PP и PS — четыре кандидата необязательного эксперимента;
LDPE и прочие полимеры требуют проверки маркировки. Покрытие данных ещё проверяется;
по внешнему виду полимер достоверно определяется не всегда.

Подробности: [дизайн-документ](docs/ml_system_design_doc.md),
[профиль московского пилота](docs/pilot_policy.md).

## Быстрый старт

Нужен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pre-commit install
ruff check .
ruff format --check .
pytest
pre-commit run --all-files
```

Pre-commit запускает Ruff, форматирование и проверки YAML/TOML, конфликтов,
окончаний строк, крупных файлов и приватных ключей. Зелёные тесты каркаса
не измеряют качество будущей модели.

## Данные и оценка

Кандидаты: [TrashNet](https://github.com/garythung/trashnet),
[Garbage Classification](https://www.kaggle.com/datasets/mostafaabla/garbage-classification),
[TACO](http://tacodataset.org/) и [WaDaBa](http://wadaba.pcz.pl/).
Лицензии, доступ, классы и дубли проверяются до использования.
Все ракурсы одного предмета остаются в одной части выборки; аугментации — только
в train. Данные и веса не хранятся в git.

Оценка включает независимые реальные фото, качество отказов, опасные ошибки,
интервалы неопределённости и сравнение со справочником. Пользовательское
подтверждение не заменяет эталонную разметку. Малый пилот 2–5 человек
проверяет usability и не доказывает эффект на популяции.

## Работа с PR

ДЗ1 находится в `hw_1`, PR направлен в пустую `main`. Пуш в `hw_1` обновляет
этот PR; до ревью ментора и кросс-ревью его не объединяем.
CI проверяет и коммиты через веб-интерфейс, которые обходят локальные хуки.
[Что изменено по ревью](docs/review_changes.md).

не доказывает пригодность для сортировочной станции (раздел 6 дизайна).
