# Waste Sorter

Учебный ML-проект: определение материала одного предмета по фотографии — пластик,
бумага, стекло, металл, органика, опасные отходы или прочее.
Проверяем, помогает ли фото принять верное решение быстрее текстового справочника.

ДЗ2 выполнено в ветке `hw_2`: проанализированы 2 527 изображений TrashNet
и 4 784 аннотации TACO, сохранены manifest, графики и выводы. Запущены B0
и цветовой baseline на четырёх материалах. Семиклассовая модель, API и пилот
ещё не готовы; цели MVP не выдаются за измеренные результаты.

[Отчёт EDA с девятью графиками](reports/eda/README.md) ·
[этапы решения ДЗ2](docs/ml_system_design_doc.md#23-этапы-решения-задачи)

## Как это будет работать

1. Пользователь загружает фото одного предмета в веб-демо поверх FastAPI.
2. Лёгкий классификатор возвращает материал или отказ от ответа.
3. Возможная опасность имеет приоритет над обычной инструкцией; низкая уверенность
   требует пересъёмки, проверки маркировки или обращения к справочнику.
4. Условия приёма определяются отдельным проверенным профилем оператора.
   Без профиля результат — `unknown`, а не обещание подходящего контейнера.
5. Добровольный фидбэк поступает в обучение только после проверки метки
   и при отдельном согласии на хранение фото.

Материал и приём — разные понятия. `other` не означает «не перерабатывается».
PET, HDPE, PP и PS — четыре кандидата необязательного эксперимента;
LDPE и прочие полимеры требуют проверки маркировки. Покрытие данных ещё проверяется;
по внешнему виду полимер достоверно определяется не всегда.

Подробности: [дизайн-документ](docs/ml_system_design_doc.md),
[профиль московского пилота](docs/pilot_policy.md).

## Быстрый старт

Нужен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -c requirements/hw2.txt -e ".[dev,eda]"
pre-commit install
ruff check .
ruff format --check .
pytest
pre-commit run --all-files
```

Pre-commit запускает Ruff, форматирование и проверки YAML/TOML, конфликтов,
окончаний строк, крупных файлов и приватных ключей. Зелёные тесты каркаса
не измеряют качество будущей модели.

## Данные и оценка

Фактически загружены изображения [TrashNet](https://github.com/garythung/trashnet)
и аннотации [TACO](http://tacodataset.org/).
[Garbage Classification](https://www.kaggle.com/datasets/mostafaabla/garbage-classification),
[WaDaBa](http://wadaba.pcz.pl/) и RealWaste остаются кандидатами, их EDA пока не проводился.
Версии и checksum источников сохранены. В TrashNet есть 3 конфликтных точных дубля,
а organic/hazardous и проверенный other отсутствуют. TACO содержит только 2 батарейки;
права на фото и дефекты аннотаций требуют отдельного разбора.
Найденные candidate-группы остаются в одной части выборки; настоящие ID предметов
ещё требуют аудита. Аугментации в дальнейшем применяются только к train. Данные и веса не хранятся в git.

Оценка включает независимые реальные фото, качество отказов, опасные ошибки,
интервалы неопределённости и сравнение со справочником. Пользовательское
подтверждение не заменяет эталонную разметку. Малый пилот 2–5 человек
проверяет usability и не доказывает эффект на популяции.

## Воспроизвести ДЗ2

После установки окружения:

```bash
python scripts/download_data.py   # первый запуск требует интернета
python -m waste_sorter.eda        # изображения + аудит аннотаций, таблицы и графики
python -m waste_sorter.baseline   # B0 и RGB baseline: только train/validation
```

Сырые данные остаются в `data/raw` вне git. В репозитории —
[отчёт](reports/eda/README.md), [summary](reports/eda/summary.json), manifest,
пары-кандидаты, статистики аннотаций и результаты validation.
Подтип пластика, реальная переработка и recall опасных предметов этими моделями не проверялись.
Текущий split предварительный: candidate-группы не равны подтверждённым предметам.
